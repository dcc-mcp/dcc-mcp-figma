# dcc-mcp-figma

Use the official Figma Plugin API for document operations and public dcc-mcp-core APIs for MCP and request correlation. Keep all source, identifiers, comments and documentation in English; user-facing conversation defaults to Simplified Chinese.

Figma has no embedded Python. Prefer the existing DCC-MCP Runtime for its external Python service; the plugin remains official JavaScript Plugin API code. Reuse shared Runtime selection, manifests, verification, dependency isolation and lifecycle contracts when available. Never bundle/download another interpreter, silently fall back to system Python, or invent a Runtime installer/launcher. Runtime negotiation is not payload integrity, actual ABI/dependency probing or document/pairing authority. The current public Runtime lacks a usable process-launch contract; `runtime-preflight` must fail closed and state the upstream blockers. Keep explicit developer/test Python entry points compatible without claiming managed deployment readiness. See docs/RUNTIME_INTEGRATION.md.

This repository is an unreleased adapter. Never describe a fixture, source check, successful transport or undo boundary as native document persistence. Native acceptance requires an approved existing Figma host, a Figma-assigned plugin ID, approved loopback plugin access, real read/write/export, and same-file reopen readback.

The selected route is local development-plugin deployment following the review of Figma's Community guidelines; Community publication remains on hold. Preserve the implementation. Do not publish it to Community, delete it, contact Figma, conceal its MCP/AI functionality, or replace its architecture without further instruction. Local tests and the local-deployment choice do not establish private-use compliance. Source visibility may change only for the exact repository explicitly authorized by the user and after its publication audit; that authorization does not extend to other repositories, packages or credentials. Public source is not evidence of native acceptance or a released product. Persistent new credentials require specific confirmation. A continuing desktop denial must stop UI attempts rather than trigger a provider/context switch. See docs/PUBLICATION_AND_ROUTES.md for the retained official-MCP complementary assessment.

Do not install or start the plugin, create credentials, expand OAuth or plugin permissions, or retry a denied desktop operation without explicit authorization. Merge, package publication and release require their own task authorization and the applicable exact-head review, CI, native and release gates. They do not follow automatically from public source visibility or a showcase upload. Do not edit the original design-bridge owner's checkout. Keep Cocos discovery separate.

Use typed operations only: no arbitrary eval, remote script execution or REST canvas-write inventions. Bind every request and response to one explicitly paired plugin/document connection, reject stale responses, and invalidate the binding after an indeterminate timeout. A read-only connection must not create document markers. Keep tokens out of URLs, logs, document plugin data and Git.

Run Python contract tests and the Node Plugin API harness. Label harness evidence as synthetic. Use the existing installed SDK/toolchain; do not install dependencies implicitly.
